# REVIEW.md

List every defect you found in the starter `app/main.py` (helpers and endpoints). For each one:

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `compute_work_hours` (line 40) | Uses Python's built-in `round()`, which applies round-half-to-even (banker's rounding) instead of arithmetic round half-up (R4). | For values ending in `.005` with an even preceding digit (e.g., 8.125), it rounds down to `8.12` instead of rounding up to `8.13`. | Replaced with Python `Decimal.quantize` using `ROUND_HALF_UP`. |
| 2 | `compute_late_minutes` (lines 33-37) | (a) Compares `minutes > 10` instead of strict elapsed time > 10:00 (R2); (b) does not truncate seconds before calculation (R1); (c) assumes shift start is on the punch date, failing overnight shifts. | Punch-in at 09:40:01 for a 09:30 shift: `int(601 / 60) == 10`, which is not `> 10`, returning 0 late minutes instead of 10. For overnight shifts, comparing against local day hours breaks late calculation. | Truncated instants to whole seconds, verified strict `diff_seconds > 600`, floored elapsed minutes `diff_seconds // 60`, and anchored start time to the computed attendance date. |
| 3 | `compute_overtime` (lines 44-47) | (a) Assumes shift end is on `date_str`, breaking overnight shifts where shift end falls on the next calendar day; (b) does not enforce the 30-minute threshold (R3). | An overtime duration of 15 minutes returned 15 instead of 0. For overnight shifts (22:00–06:00), punch-out at 06:40 next day calculated against previous day's 06:00 yielded negative or huge values. | Incremented shift end date by 1 day for overnight shifts, and required `diff_seconds >= 1800` (30 mins) before returning `diff_seconds // 60`. |
| 4 | `POST /employees` (lines 78-85) | Race condition: uses check-then-insert (`find_one` then `insert_one`) without a database unique index on `emp_code`. | Parallel concurrent `POST /employees` requests with identical `emp_code` both insert documents and return 201. | Created a unique index on `{"emp_code": 1}` at startup, and caught `DuplicateKeyError` to return HTTP 409. |
| 5 | `POST /employees` (lines 78-85) | Missing input validations: allowed identical `shift_start` and `shift_end` (violating contract), stored naive datetime via `datetime.now()`, and leaked internal ObjectId `_id`. | Passing `shift_start="09:30"` and `shift_end="09:30"` returned 201 instead of 422. `created_at` was not formatted as integer epoch milliseconds. | Added Pydantic validator ensuring `shift_start != shift_end`, stored UTC BSON date, and serialized `created_at` as epoch milliseconds integer. |
| 6 | `GET /employees` (line 93) | Pagination off-by-one error: `skip = page * page_size` skips items 0–19 when `page = 1`. | Querying `GET /employees?page=1` returned items starting from index 20, missing the first page completely. | Corrected offset formula to `skip = (page - 1) * page_size`. |
| 7 | `GET /employees` (line 94) | Unfiltered total count: `total = db.employees.count_documents({})` counts the entire collection ignoring the `department` filter parameter. | Querying `GET /employees?department=Sales` returned `total` equal to company-wide headcount rather than sales count. | Filtered count using `total = db.employees.count_documents(q)`. |
| 8 | `GET /employees` (line 95) | Missing sorting: did not sort by `emp_code` ascending as required by the OpenAPI specification. | Employees returned in non-deterministic MongoDB insertion order. | Added `.sort([("emp_code", 1)])`. |
| 9 | `POST /attendance/punch-in` (line 101) | Missing employee verification: if `emp_code` does not exist, `emp` is `None`, and `emp["shift_start"]` raises an unhandled `TypeError` (HTTP 500). | Punch-in request with an unknown `emp_code` returned 500 Internal Server Error instead of 404 Not Found. | Added explicit check: if `emp is None`, raise `HTTPException(404, "employee not found")`. |
| 10 | `POST /attendance/punch-in` (lines 104-118) | Race condition: check-then-insert allows duplicate attendance logs for the same employee and date under concurrent requests. | Two concurrent punch-in requests at the same instant both returned 201. | Created a unique compound index on `{"emp_code": 1, "date": 1}` at startup and caught `DuplicateKeyError` to return HTTP 409. |
| 11 | `POST /attendance/punch-in` (lines 102-103) | Timezone and calendar date error: uses naive local timestamp `ts.date().isoformat()` and ignores overnight shift boundary rules (R1). | Punch-in at 05:00 IST for a 22:00–06:00 overnight shift was tagged with today's calendar date rather than yesterday's shift date. | Converted instants to IST, applied R1 overnight shift logic to determine attendance date, and truncated timestamps to whole seconds. |
| 12 | `GET /attendance` (lines 144-147) | In-memory sort and full collection scan: loads entire collection via `list(db.attendance_logs.find(q))` into Python memory and sorts in Python. | High memory consumption, latency spikes, and OOM crashes when querying across 100,000 records. | Moved sorting, skipping, and limiting directly into the MongoDB query cursor using `.sort([("date", -1), ("emp_code", 1)]).skip(skip).limit(page_size)`. |
| 13 | `GET /attendance` & `POST /attendance/punch-in` (lines 119, 149) | Contract violation: injected `"id": str(doc["_id"])` into attendance record responses. | Response validation failed because attendance documents have no ID field in the OpenAPI schema. | Excluded MongoDB `_id` and omitted `id` from output schemas. |
| 14 | `GET /health` (lines 72-74) | False positive health check: unconditionally returns `{"status": "ok"}` without testing the MongoDB connection. | When MongoDB was stopped or unreachable, `/health` still responded with 200 instead of 503 Service Unavailable. | Added `client.admin.command("ping")`, catching exceptions and returning HTTP 503. |
| 15 | Instants input validation (lines 65, 102) | Lacked strict type validation for epoch milliseconds: accepted floats, strings, and seconds-looking integers (< 100000000000). | Submitting a seconds-looking timestamp (e.g., 1718000000) was accepted instead of returning 422. | Enforced strict Pydantic `EpochMillis` validation (`ge=100000000000, le=4102444800000, strict=True`) and whole-second truncation. |

## Examined and Decided Was Not a Defect
1. **Customer-Supplied `emp_code`**: Examined whether the API should auto-generate employee IDs. The contract explicitly defines `emp_code` as an external, customer-provided business code (e.g. `EMP0001`) that is unique and immutable; not generating it on the server is by design.
2. **Default Pagination Parameters**: Examined default query parameters (`page=1`, `page_size=20`) in `GET /employees` and `GET /attendance`. These defaults match the OpenAPI specification and are not defects.
